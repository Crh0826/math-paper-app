## 这一版修的是「用户实际用不了」的三件事

### 1. DeepSeek 视觉模型现在真的能用了

之前选 `vlm`（OpenAI 兼容视觉模型）填 DeepSeek，结果是 `vlm->manual`、整批「没识别出文字」。三个叠加的 bug：

| 原因 | 现象 | 修法 |
|---|---|---|
| `base_url` 无条件拼 `/v1/chat/completions` | 填 `https://api.deepseek.com/v1` → `.../v1/v1/...` → HTTP 404 | 三种写法都兼容（带 /v1、不带、直接给完整 endpoint） |
| `max_tokens=128` | V4.1-Flash 默认思考模式，推理内容吃光预算 → 正文空（`empty content`） | 提到 512 |
| 小作答框原样送 | 405×106 的分数框返回空 | 高度 <200px 自动放大 2 倍 |

实测（真实答题卡照片）：手写 `99` → 1.0s 识别正确；`2026/4053` → 1.4s 识别正确（连测 3 次全对）。

### 2. 每题的 5×5 标识「读不出」→ 现在能读

原来按固定坐标扫格子，偏 1–2px 就整串位读废。改成：
轮廓找候选（88–140px 方形）+ 按实测块宽自适应（≥108 → 5×5，88–107 → 4×4）+ **±8px 本地对齐** + 列带黑框兜底。
真实照片实测：4 个标识全部解出 `10101 / 12665 / 11198 / 05852`（题号都在题库），9 个作答单元全部正常，**速度 3.6s → 0.30s**。

### 3. 分数被 OCR 拆成两个数

模型偶尔输出 `2026 4053` 而不是 `2026/4053`，被当成"两个值"判错。现在只有"两个数正好等于对面分数的分子分母"才认作分数；`1 2` vs `3/4` 这类反例不会误并。
