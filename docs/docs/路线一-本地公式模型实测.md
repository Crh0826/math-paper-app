# 路线一实测：本地模型能不能替代云 VLM

> 结论先行：**「公式 OCR」模型（pix2tex/LaTeX-OCR 这一类）对手写答案完全不可用（0/9）**；
> 但**换成小型视觉语言模型 Qwen2.5-VL-3B，在本机 CPU 上就能做到 9/9、约 9 秒/格**。
> 已接入为独立后端 `local_formula`（离线、不上传），设置页可直接切换。

- 机器：i5-12490F（6C/12T）、31.8 GB 内存、**无 NVIDIA GPU**、torch CPU 版
- 样本：`app/out/P20261101-002/sub_S20261101-120053-63e6b9/` 下 9 张真实作答裁切
- 判对口径：`normalize.is_equivalent(识别文本, 标准答案)`，与线上判卷同一套规则

## 0. 最终结果（同一批 9 张）

| 方案 | 判对 | 耗时 | 说明 |
|---|---|---|---|
| 智谱 glm-4.5v（云） | 9/9 | 21.2s | 最准，但要联网、要 key |
| GLM-OCR + glm-4.5v 兜底（云，默认） | 8/9 | 15.4s | 公式类走 GLM-OCR |
| **Qwen2.5-VL-3B（本机 CPU，离线）** | **9/9** | **81.4s（9.0s/张）** | ✅ 已接入 `local_formula` |
| pix2tex / LaTeX-OCR（本机 CPU） | 0/9 | 0.2–1.5s/张 | ❌ 域不匹配 |
| GOT-OCR2（本机 CPU） | 跑不起来 | — | 仅 CUDA + transformers 4.x |
| zndjs `/ocrread`（第三方） | 4/9 | 54.2s | 会编造，不建议 |

本机模型的识别原文（全部判对）：

```
1-1  0.6, 2011/2012, 368     1-2  -π, -100, -2 5/7     2-1  -6
3-1  99                       3-2  2026/4053            4-1  x=3
4-2  x=3/2                    4-3  x=11                 4-4  y = 4/5
```

> 注意：本地模型会**偶发丢负号**（某次批量跑 `-6`→`6`、`-π`→`π`）。
> 所以判分侧加了规则：**只差一个负号 → 待确认**，不再直接判错（见下"防误判"）。

## 1. pix2tex / LaTeX-OCR（97.4 MB，CPU 0.2–1.5s/张）——不可用

装法（独立 venv，不动主环境）：

```bat
python -m venv E:\OCR\.tools\venv_formula
E:\OCR\.tools\venv_formula\Scripts\python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple pix2tex
```

两个坑：
1. 权重 97.4 MB 走 GitHub 只有 ~126 KB/s，**gh-proxy.com 镜像 1.3 MB/s**（50 秒下完）；
2. pix2tex 把权重放**包目录** `pix2tex/model/checkpoints/`（不是 `%LOCALAPPDATA%`），
   放错位置它每次启动都会重新下载。

| 裁切 | 期望 | pix2tex 输出 |
|---|---|---|
| 3-1.png | `99` | `\mathcal{Q}\mathcal{O}…` |
| 4-1.png | `x=3` | `\operatorname{sz}{\big{s}}` |
| 4-2.png | `x=3/2` | `\begin{array}{c}…\left\lbrace\ast\right\rbrace…` |
| 3-2.png | `2026/4053` | `\frac{\partial\mathcal{A}_b}{\langle…}` |

**0/9**；再试 5 种预处理（灰度/紧裁+白边/二值化/放大 3×/二值+放大），20 张组合 **0 对**。
不是清晰度问题，是**域不匹配**：pix2tex 语料是 arXiv 论文里的印刷公式。

## 2. GOT-OCR2_0（580M）——本机跑不起来

- 权重 1.37 GB（hf-mirror 可下），缺 `verovio`/`tiktoken` 已补；
- `chat()` **硬编码 `.cuda()`**（6 处）→ CPU 直接 `AssertionError: Torch not compiled with CUDA enabled`；
- 改成 CPU 后卡在 `'DynamicCache' object has no attribute 'seen_tokens'` —— 它按 transformers 4.x 写，
  本机 5.22；降级在 Python 3.14 上大概率装不上，不值得为它降级整条链。

## 3. Qwen2.5-VL-3B（本机 CPU）——可用，已接入

```bat
:: 依赖（一次装好，之后离线）
E:\OCR\.tools\venv_formula\Scripts\python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple ^
    torch torchvision transformers accelerate qwen-vl-utils pillow
:: 权重（HF 镜像）
set HF_ENDPOINT=https://hf-mirror.com
```

实测：模型加载 8.9–21s（首次冷启动），单张 **6.9–11.9s**，9 张合计 81.4s，**9/9 判对**。
主程序通过 `app/tools/local_vlm_bridge.py` 子进程调用，**主环境不需要 torch**（便携版也能用，
只要 venv 在 `.tools\venv_formula`）。

配置（`config.json`）：

```json
"ocr": {
  "backend": "local_formula",
  "local_formula": {
    "python": "E:\\OCR\\.tools\\venv_formula\\Scripts\\python.exe",
    "model": "Qwen/Qwen2.5-VL-3B-Instruct",
    "fallback": true,
    "timeout_s": 900
  }
}
```

设置页 `/settings` 里也能直接选「本机视觉模型（Qwen2.5-VL-3B，离线）」，并显示 python 是否找到。

## 4. 防误判：只差一个负号 → 待确认

本机模型偶发把 `-6` 读成 `6`、`-π` 读成 `π`（云模型也出现过）。`grade._judge` 新增规则：

> 把识别结果里**某一个数的负号翻一下**就能与标准答案等价 → 判 **unsure（待确认）**，
> 理由写「只差一个负号（可能是符号没识别出来）」。

已验证：`6` vs `-6` → 待确认；`7` vs `-6` → 仍判错（不会放水）；`π,-100,-2 5/7` vs `-π,-100,-2(5)/7` → 待确认。

## 5. 适用与不适用

- ✅ 离线/隐私场景：学校机房、无网教室；夜间批量判卷（9 秒/格可接受，判卷本身是异步的）
- ❌ 即时要分：本机慢，建议仍用云 VLM（glm-4.5v，约 2 秒/格）
- ❌ 整页 PDF 版面解析：用 GLM-OCR
- ❌ 训练/微调：本机无 GPU，不做（要提分走"云 GPU 微调 + 真实手写数据"路线）
